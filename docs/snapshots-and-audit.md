# 参数快照、批量写入与审计

## 快照格式

参数快照使用 `servo-parameter-snapshot/1.0`，保存以下信息：

- 设备 ID、设备名称和 Profile 版本；
- 创建时间和用户标签；
- 每个参数的 Profile 参数 ID、16 位原始值和解码后的工程值。

恢复前必须连接设备。后端只接受设备 ID 和 Profile 版本均与当前配置一致的快照；比较和写入以原始值为一致性依据，工程值用于显示。

## 选择性批量写入

批量写入不会自动应用参数或写入 EEPROM，执行顺序为：

1. 验证参数存在、可写、数值范围和精度；
2. 拒绝重复参数；
3. 读取全部选中参数并执行写前值比较；
4. 任一写前值不一致时，整批不开始；
5. 写入阶段逐项执行 FC06，并立即使用 FC03 回读；
6. 首个通讯或回读错误发生时停止，返回已经完成的项目；
7. 若 Profile 定义了对应操作，用户另行确认“应用参数”或“持久化参数”。

确认短语包含实际项目数，例如 `批量写入 12 项`，避免快照选择变化后沿用旧确认。

## SQLite 审计

应用启动时在 Tauri 应用数据目录创建 `servo.db`，使用 WAL 日志和 FULL 同步模式。数据库包含：

- `audit_entries`：配置导入、连接、单项/批量写入、参数应用、持久化、快照导出和比较；
- `parameter_snapshots`：每次由应用读取并导出的完整快照 JSON。

参数写入、应用和持久化操作在访问设备前写入 `attempt` 记录，完成后写入 `success`；设备拒绝、超时或回读不一致写入 `failure`。批量写入还会逐项记录已完成的参数，因此部分完成不会被误报成整批成功。

SQLite 审计只证明软件发出的操作及其收到的响应，不代替设备断电后的持久化验收。
