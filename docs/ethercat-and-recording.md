# EtherCAT 配置、监控与通信录制

通信工作台包含独立的录制/解析和 EtherCAT 主站入口。原有 Modbus Profile 1.0、
串口独占、FC03 有限重试和 FC06 不自动重发契约保持不变。

## 使用入口

1. 点击“开始录制”，再使用原有模拟器或串口功能。录制不依赖曲线显示开关。
2. 开始录制后自动跟随最新已落盘报文；也可从历史会话打开录制，检索整个会话的来源、方向、协议、事务、事件和十六进制字节。
   暂停跟随、滚动表格、选择报文或翻页不会停止录制。
3. 使用文件选择器打开会话目录、单个 PCAP/PCAPNG，或包含全部分卷的目录；也可直接输入完整路径。
4. EtherCAT 帧点选后显示标准字段。可导入解析映射，或从当前主站发现结果填入邮箱地址。
5. 在线网卡捕获单独启停，始终独立保存 PCAPNG；若统一录制同时开启，还会写入共同时间线。
   同时捕获主站自己的网卡会产生两个来源的观测，不做猜测性去重。

## 标准解析范围

- Ethernet、嵌套 VLAN、EtherType 0x88A4、EtherCAT Type 1、多 Datagram。
- NOP、APRD/APWR/APRW、FPRD/FPWR/FPRW、BRD/BWR/BRW、LRD/LWR/LRW、ARMW/FRMW。
- 地址、索引、长度、循环/后续标志、IRQ、WKC、原始负载；截断或长度矛盾显示错误。
- 已知物理地址的 AL 状态、AL 状态码、DC 系统时间。WKC 不自动推断预期值。
- 显式邮箱映射下的邮箱头、CoE SDO 快速传输/分段头/Abort、FoE、SoE、EoE、AoE 标准头。
  邮箱深层业务和离线跨帧重组尚未实现；分段保留原始字段，不冒充完整对象。
- 显式逻辑 PDO 映射的 1～64 位整数、小端位字段、有符号和缩放解码。
  64 位原始整数用字符串显示，工程值为浮点近似。
- 不内置厂商对象字典，不根据负载猜邮箱或 PDO，不自动导入 ESI 或重建 FMMU 配置。

解析映射参考 `examples/ethercat-decode.example.json`。邮箱项包含 `station`（配置站地址）和
`offset`（实际邮箱寄存器起始地址）；PDO 项包含 `logicalAddress`、`bitOffset`、
`bitLength`、`signed`、`scale` 和 `unit`。必须来自当前实际工程配置。

## 主站配置与监控

Windows 需要单独安装 Npcap 并重启应用。主站采用随源码提供的 SOEM，通过 MSVC 静态编译，
Npcap 动态加载；不需要用户额外构建或寻找 SOEM DLL。

连接前选择专用网卡并输入“接管 EtherCAT 总线”。此动作会初始化从站和邮箱、请求 PRE-OP，
属于主动总线操作。先停用其他主站并确认设备处于适合配置的状态。

发现列表显示位置、配置地址、Vendor/Product/Revision、AL 状态和错误码。
导入 `ethercat-1.0` Profile 后，只有 Vendor/Product 匹配且从站声明 CoE 时才能访问对象。
Profile 示例在 `examples/ethercat-profile.example.json`；示例标识和地址均虚构。

对象以 `index/subIndex` 标识，支持 1/2/4/8 字节整数；`min/max` 使用十进制原始整数
字符串，`scale` 只用于工程值显示。默认只读。写入要求：对象允许写入、值在范围内、
输入“写入 对象ID”、重新读取值与界面原始值一致、先持久记录写入尝试、再发送并回读。
超时或回读不一致会使显示值过期，不自动重复应用层写入。SOEM 保留标准链路级重试。
应用没有自动保存 EEPROM、恢复出厂值或执行厂商操作的路径；此类对象必须由使用者明确定义。

监控最多选择六个对象，以 SDO 轮询并绘制最近 300 点。轮询间隔为一轮读取后的等待，
不是实时 PDO 周期；主站不进入 OP、不使能伺服、不发送周期运动输出。

## 录制契约

统一录制位于应用数据目录 `recordings/session-*`：

- `session.json`：格式版本、开始时间、时间单位、容量、采集范围、初始配置快照与故障触发设置。
- `annotation.json`：用户保存的会话名称和备注，不改写原始分卷。
- `records-NNNN.jsonl`：有界队列、后台单写者、16 MiB 分卷；每行保存原始字节及事件。
- `summary.json`：正常结束/失败状态、接收/写入/队列丢弃/未写入计数，以及故障触发时间和主动淘汰计数。
- 可导出其中以太网帧为 PCAPNG。串口和模拟器不伪装成以太网包。

默认容量 1024 MiB，允许 16～16384 MiB。达到上限停止录制，不删除旧文件。
队列溢出丢弃新记录并计数，通信事务继续；停止时先解除入口再排空队列。
断电/崩溃只能恢复已落盘的完整行，损坏尾行显示警告；没有完成摘要不能视为正常结束。
持续写入时每 100 条或经过 250 ms 执行 flush，空闲时每 250 ms flush；“已写”仅统计成功 flush 的记录。
正常结束与分卷执行 sync_all。flush 只表示提交给操作系统；异常掉电仍可能丢失未同步内容。
结束摘要先写临时文件并同步，再重命名；摘要失败会反馈到录制状态，不显示为完整成功。

串口每次 read/write 的实际字节都记录，包含部分收发、超时、CRC 错误、每次事务和缓冲
清空事件。OS 接受写入不等于已在线缆发送；缓冲区清除掉的未读取字节无法追回。
不同串口连接通过来源和事务编号区分；模拟器记录语义事件，明确注明模拟来源。

在线捕获位于 `captures/capture-*`，每卷 `frames-NNNN.pcapng`，并保存最终摘要。
摘要使用临时文件、同步和重命名；摘要保存失败会保留原捕获错误并显示失败，不能视为完整结束。
可录所有可见以太网协议或仅 EtherCAT，内核丢包和录制队列丢弃分别统计。
方向无法确定时标为 unknown，原始 PCAPNG 保留捕获长度和原长。
PCAPNG 默认微秒时间戳，导入纳秒时间戳在界面转换为微秒并标注精度；输入文件保持不变。
捕获范围取决于主站位置/TAP/镜像接线，不能保证看到其他设备所有通信。

## 全会话检索与实时跟随

JSONL 会话在应用数据目录的 `recording-indexes` 建立派生 SQLite 索引；原始分卷不被改写。
首次打开扫描完整会话，后续只索引新增完整行；未完成尾行等待下次刷新，损坏行保留告警。
索引保存文件位置及可检索元数据，按方向和事务建立索引，原始字节仍从原文件读取。
未筛选的最新页倒序读取索引，避免跳过全部历史记录；PCAPNG 导出单次顺序扫描各卷。
检测到文件缩短、已封卷文件变化或删除时重建索引；录制文件按追加写入契约使用，索引不是防篡改校验。
缓存可删除后重建，占用空间独立于录制容量上限。首次索引和任意子串搜索的耗时仍随会话规模增长。

搜索框对来源、协议、方向、事务编号、事件文本和以空格分隔的十六进制字节进行大小写无关子串匹配。
时间范围（本地时间输入，端点包含）、来源/协议精确匹配、方向和 Modbus 站号/功能码/包含地址/事务结果筛选同时作用于全会话，显示总匹配数和当前区间。
站号、功能码、地址和结果从拼接并校验后的事务派生，关联该事务的全部收发与事件；失败、缺少结束事件与成功分别标记。缺失/损坏摘要、计数矛盾、缺失分卷和损坏尾行均提示完整性问题。
实时跟随约每秒读取一次最新 100 条已落盘匹配记录并滚动到最新行；不能保证精确刷新周期，也不代表线缆级实时捕获。
暂停、切换会话或修改筛选会使过期查询失效；失败停止跟随并保留错误。录制仍由后台独立负责。

外部 PCAP/PCAPNG 文件或目录中的全部分卷先流式转换为派生 JSONL 缓存，再复用统一索引，支持全量关键词和时间检索。
分卷按文件名排序，来源保留文件名与原接口信息；不做猜测性去重。源文件增删、大小/修改时间或捕获摘要改变后重建缓存。
构建期间源文件变化会返回错误，需停止捕获后重开；单帧超过 128 KiB 或损坏时保留此前可用记录并明确告警。
PCAP 缓存会额外保存一份派生数据，空间独立于录制容量限制；源文件与源目录保持不变，未提供 PCAP 实时跟随。
打开/翻页/解析和逐点浏览仅离线读取，绝不将历史报文重发到设备。

## 会话配置、管理与历史曲线

开始录制时保存当前 Modbus Profile、连接参数、通信设置，以及已导入的 EtherCAT Profile / 连接信息和显式解析映射。
Profile、连接或通信设置变更由各自后端所有者写入 `recording-context` 事件；手动映射通过“保存映射到录制上下文”生效。
上下文快照独立于当前界面配置，历史 EtherCAT 详情按记录序号选择当时的映射；旧会话或外部 PCAP 缺少映射时才使用界面手动配置。
单条编码后的记录上限为 1 MiB，超过上限会终止录制并上报未写入，不留下无法检索的超长行。

会话列表显示名称、大小和摘要完整性提示；名称与备注使用独立文件保存。时间概览读取实际报文的首末时间及记录数量，
因此表示观测跨度，不是设备在线时长。没有时间戳的 PCAP 包不参与首末时间计算。

历史曲线按来源、协议、站号、地址及时间范围读取，每页最多 2000 个实际样本。
Modbus 仅使用校验通过、请求响应匹配且记录到成功结束的 FC03 事务；状态寄存器按当时 Profile 的有符号类型和小数位缩放，
缺少状态定义时显示原始值。模拟器保存带定义、原始值和工程值的实际状态采样，保持模拟来源，不伪造 Modbus 报文。
点击曲线或移动采样点滑块会定位原始记录/完整事务并暂停实时跟随；支持每 0.5 秒浏览一个样本。
曲线按实际时间分布，各定义独立缩放，连线不补造缺失样本；这不是按原始时间间隔倍速回放。
外部 PCAP 的 EtherCAT 过程数据历史曲线和跨帧对象重组不在此通道的重建范围。

## 故障触发录制

可在开始前启用一次性故障触发，配置故障前 0～300 秒和故障后 1～300 秒。
默认匹配 Modbus 失败事务结束事件（含超时、CRC/LRC、设备异常），或显式 `device-fault` 事件；也可输入事件文本关键词。
不根据未定义的厂商状态位猜测设备故障。

后台写入线程保留最多 16 MiB 的故障前缓冲，按时间和容量主动淘汰旧记录并单独计数，和队列溢出区分。
配置变更即使在等待触发时也会落盘，以便解释保留下来的前置报文。
首次触发后保存故障前缓冲及故障后窗口，窗口结束会自行停止，即使没有后续报文也会结束。
未触发便手动停止时丢弃缓冲，只保留配置事件；摘要中的 `triggeredAtUs` 为空，不能理解为已抓到故障。
故障前环形缓冲尚未落盘的内容在进程崩溃或断电时无法恢复。

## Modbus 离线事务解析

点击 Modbus 报文后，按来源、协议和事务编号从整个会话取齐相关记录，不受当前搜索、方向或分页限制。
RTU/ASCII 均拼接实际收发片段，复用原有 CRC/LRC 校验；每次重试的独立编号分别解析。
当前覆盖应用实际使用的 FC03、FC06 及异常响应：站号、功能码、起始地址、数量、原始寄存器值、
写入回显、异常码与应用观测耗时。请求与响应不匹配、坏校验、缺失字节和未记录到结束事件明确显示。
保留清空缓冲、部分收发、错误及结束结果等原始事件；不从事件中的请求文本补造未采集字节。
数值不自动套用当前 Profile 缩放，应用观测耗时不是线缆传输时间。有录制缺口时仍显示完整性告警。
其他功能码保留原始内容，不冒充已解析。

## 验证与设备验收

执行 `pnpm test`、`pnpm build`、`cargo test --manifest-path src-tauri/Cargo.toml --locked`、
`cargo clippy --manifest-path src-tauri/Cargo.toml --locked -- -D warnings`。
测试覆盖解析边界、PCAPNG 往返、全会话筛选/增量索引/重建、录制尾行恢复、队列溢出、容量和分卷失败、
写入/flush/sync/摘要失败、停止排空、Modbus CRC 失败及重试关联、ASCII LRC、写回显和缺失响应。
测试还覆盖故障前淘汰、配置保留、故障后空闲自动停止、跨卷时间筛选、捕获摘要失败上报，以及配置变更前后历史缩放。
进程强退测试启动真实录制子进程、等待至少 400 条完整记录 flush 后终止，再检查原始记录可恢复且缺失摘要被告警；
辅助子进程入口只由该测试调用，不作为普通测试单独运行。这验证进程强退恢复，不等同于物理断电或真实磁盘满。
前端回归覆盖跟随暂停、跨会话旧响应丢弃、详情请求失效和索引错误；文件写入失败使用受控注入，不等同于物理断电验收。

实机仍需核对：独占总线上的发现和 PRE-OP 状态；匹配 Profile 的读取和低风险写入回读；
持续录制下帧数、驱动丢包、时序与 Wireshark 字段对照。软件测试不等于设备兼容性认证。
