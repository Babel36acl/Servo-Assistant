# 从伺服器手册生成 Servo Profile

## 目标与边界

从指定型号和版本的伺服器手册中提取 Modbus 通信设置、参数和只读状态量，整理成 Servo Assistant Profile 1.0 JSON，并为每项保留可回查的 PDF 页码证据。手册没有明确的信息保持为未确认项；不得用常见值、其他型号或参数名称猜测设备事实。

此 Skill 只制作离线配置文件，不连接设备、不发送 Modbus 请求、不写入参数，也不把手册或厂商参数库加入仓库。用户后续单独授权的设备操作仍需遵守项目的写入确认流程。

## 适用场景

- 用户提供伺服驱动器手册 PDF，并要求生成或修订 Servo Profile JSON。
- 用户要求核对已生成 Profile 中的 Modbus 地址、数据类型、缩放、范围或通信设置是否能由手册支持。
- 手册表格有 OCR、跨页、合并单元格、十六进制地址或参数编号换算，需要复核后再映射到 JSON。

## 流程

1. **锁定资料对象。** 记录 PDF 文件名、设备厂商/型号、手册修订版和适用固件范围。不同型号、修订版或接口协议的地址表不得合并。先读取仓库的 `docs/profile-v1.md` 和 `examples/servo-profile.example.json`；若 Skill 被移出仓库，则要求用户提供目标 Profile 契约。
2. **读取并复核 PDF。** 提取文本和表格时保留印刷页码、PDF 页序、章节及表名；有可用的 `pdf` Skill 时遵循其读取约定。遇到扫描件、OCR 错乱、列错位、脚注或跨页表格时渲染原页核对；无法确定列对应关系时标为待确认，不按邻近行补值。
3. **建立证据表。** 每个候选字段记录：JSON 路径、规范化值、PDF 页码/章节/表格、手册原文或原始写法、换算过程，以及状态（明确、按手册公式推导、待确认）。ID 和显示名称可按项目命名约定生成，但注明它们是 Profile 标识，不是手册里的设备事实。
4. **区分参数名与通信地址。** `P145`、`Pr1.01` 等参数编号不自动等于 Modbus 地址。只有手册明确给出地址，或明确给出可复算且适用于该型号的地址公式时才转换；保留原编号、公式、进制和地址偏移约定。遇到 4xxxx、一基编号或十六进制写法时，未确认协议偏移前不做减一或基址换算。
5. **检查编码和单位。** 按手册确认 16 位有符号/无符号类型、工程范围、默认值、单位、读写属性、枚举、适用模式、重启要求和缩放。`decimals` 仅表达十进制位数；若手册定义 32 位、多寄存器、浮点、字节/字序规则或非十进制缩放，不能强塞进 Profile 1.0，应列为当前运行时不支持。
6. **生成 Profile。** 只把证据完整的参数写入 `parameters`，只把明确为只读的状态量写入 `statuses`。通信类型、站号、波特率、校验位、停止位和超时必须有资料或用户确认；`apply`/`persist` 命令和状态码仅在手册明确描述其语义及值时填写，否则省略 `operations`。Profile 的 `risk` 是上位机确认等级，不是伺服器原生字段；按手册说明的影响提出保守建议，并在证据表标记为建议、说明依据，等待用户审阅。
7. **处理缺项。** 不得补造 `defaultValue`、`min`、`max`、`rawType`、`decimals`、`access` 或通信设置。完整信息不足的参数从可导入 JSON 中省略，并列入待确认表；若无法形成至少一项完整参数或无法确定必需的通信字段，则先交付提取/待确认报告，不声称已生成可导入 Profile。
8. **校验与交付。** 检查 JSON 语法、Profile 1.0 必需字段、ID/地址重复、数值范围、16 位编码能力及原始整数缩放。按用户指定路径保存；未指定时使用不覆盖现有文件的新文件名。最终交付 Profile JSON 和独立的证据/待确认报告；明确列出已省略项目和运行时不支持项。不得把页码、证据备注或其他非契约字段塞进 JSON。

## Profile 1.0 映射速查

| 来源信息 | Profile 字段 | 要求 |
| --- | --- | --- |
| 设备名称/型号 | `device.id`, `device.name`, `device.profileVersion` | `id` 可规范化生成；不可把型号或固件适用范围猜出来 |
| 串行通信章节 | `transport` | 必须确定 RTU/ASCII、站号、波特率、8 数据位、校验位、停止位和超时 |
| 可读写参数表 | `parameters[]` | 至少一项；地址、16 位类型、缩放、范围、默认值和访问属性均有依据 |
| 状态/监视表 | `statuses[]` | 只放手册明确的只读寄存器；没有则省略或为空数组 |
| 应用/保存章节 | `operations` | 命令寄存器、命令值、状态寄存器、成功值和超时语义全部有依据才配置 |

`address` 是运行时直接使用的 0..65535 Modbus 保持寄存器地址。手册采用其他编号体系时，必须从手册或用户确认中取得转换规则。Profile 1.0 仅支持 `u16` / `i16`，`decimals` 为 0..6；工程值按 `raw = engineeringValue × 10^decimals` 编码，范围、默认值和枚举值必须能精确编码到 16 位整数。

顶层 `schemaVersion` 固定为 `1.0`，`parameters` 至少一项。`transport.kind` 仅支持 `modbus-rtu` / `modbus-ascii`，站号为 1..247，数据位固定 8，停止位为 1 或 2，校验位为 `none` / `even` / `odd`，且 `defaultBaudRate` 必须包含在 `allowedBaudRates` 中。参数的 `semanticId`、`parameterId` 和地址须唯一；状态项的 `id` 和地址须唯一。若定义 `operations`，命令寄存器与状态寄存器不能相同，且至少提供 `apply` 或 `persist`。

## 禁止的捷径

| 诱因 | 正确处理 |
| --- | --- |
| “赶时间，按常见伺服默认 19200、8N1 填上就行” | 不确定的通信字段会改变连接行为；列出缺项并询问，不把常见值当手册事实。 |
| “参数表里的 P 号看起来就是寄存器地址” | 回到通信映射章节找明确地址或型号内公式；没有证据就不映射。 |
| “没有默认值，填范围中点或当前示例值即可” | 缺少默认值的参数不进入可导入 JSON，列为待确认。 |
| “表格没写只读，那就当可写” | 访问属性未证实前不生成该参数项；不能通过 Profile 解除设备限制。 |
| “另一个型号同系列，地址和操作码应该一样” | 地址、缩放和命令只适用于当前资料明确覆盖的型号/版本。 |
| “JSON 能解析就代表 Profile 已完成” | 还要检查项目契约和设备证据；结构通过不等于设备兼容或现场验收。 |

## 输出格式

1. `*.servo-profile.json`：仅在必需字段齐全且至少包含一项完整参数时交付，注明这是待用户审阅后导入的静态配置。
2. `*.servo-profile-review.md`：列出 PDF 身份、参数/状态映射证据、换算、风险等级建议、被省略项、待确认问题和不支持项。每项事实均带 PDF 印刷页码或 PDF 页序及章节/表名。
3. 若无法生成可导入 JSON，说明具体缺少哪些字段，并提供已提取信息，不生成带虚构占位数值的“看似可用”配置。
